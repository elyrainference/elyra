# Decisions (append only)

Format: date — decision. Why. Rejected.

- 2026-11-04 — **One Node process serves router, API, p2p and the static site (`router/server.mjs`).** One command, same-origin panel, no CORS in the common case. Rejected: keep separate mirror server on :8080 (two processes, two ports, app→api cross-origin).
- 2026-11-04 — **No dependencies, no build.** Node stdlib `crypto`/`http`/`fetch`. The router must be auditable by the person running it. Rejected: Express/TypeScript/bundler.
- 2026-11-04 — **Ed25519 receipts, simulated settlement.** Real signed receipts are the durable part of the design; the chain adapter plugs in later behind `settle()`. Rejected: faking a wallet/tx flow that looks real.
- 2026-11-04 — **Ship a simulated market, labelled.** An empty network makes a router look broken. Simulated peers carry `simulated:true`, never settle, always show `SIM`. Rejected: hiding them (nothing to route to) or blending them in unlabelled (dishonest).
- 2026-11-04 — **TEE is a claim until attestation exists.** UI says `CLAIMED`/`DEMO`; `privacyScore` 0.8 not 1.0; local upstream = 1.0. Rejected: a "verified" badge without a verifier.
- 2026-11-04 — **`auto` hides the demo engine.** Otherwise a free local stub always wins on price. It still answers when asked by name or when nothing else exists.
- 2026-11-04 — **Speed is only learned from calls ≥150 ms.** Sub-150 ms stub calls produced absurd tok/s and distorted ranking.
- 2026-11-04 — **Price quote × 1.05 ceiling per request.** Lets a provider round, blocks a bait-and-switch between gossip refreshes.
- 2026-11-04 — **Landing edited in place.** It is a saved WordPress/WebGL mirror; regenerating loses the 3D scene. Only copy, meta, `site.js` labels and one inline font-size were changed.
- 2026-11-04 — **Logos via `@lobehub/icons-static-svg`, CSS-masked, committed locally.** Offline-capable, themeable with `currentColor`. Vendor marks are trademarks of their owners; shown for identification only.
- 2026-11-04 — **Robinhood Chain via an escrow + cumulative-voucher channel.** One tx per deposit and one per provider payout, nothing on-chain per request. Rejected: per-request txs (gas dominates), off-chain-only "settled" flags.
- 2026-11-04 — **Money is USDG (ERC-20), gas is ETH.** Prices are already dollars, so a dollar stablecoin removes the oracle and the manual exchange rate entirely (supersedes the earlier ETH + `usdPerEth` design). Cost: an `approve` tx, a Paxos-controlled upgradeable token (transfers may revert, controller can burn), and 1-unit ($0.000001) rounding per receipt. Testnet uses our own labelled `MockUSDG` because the testnet explorer lists several unofficial "USDG" tokens and the official docs list only mainnet.
- 2026-11-04 — **Vouchers are secp256k1/EIP-712, receipts stay ed25519.** EVM can verify the first cheaply; the second is the node identity and costs nothing off-chain. A separate wallet key is bound to the node key by signature. Rejected: one key for both (ed25519 is not EVM-verifiable).
- 2026-11-04 — **Provider extends credit (`creditUsd`, default $0.02) instead of requiring prepayment per call.** Keeps latency flat; worst-case loss per consumer is bounded and checked against on-chain deposit. Rejected: a voucher before every request (extra round trip).
- 2026-11-04 — **Both sides must use the same escrow or no route.** Avoids half-settled traffic between simulated and on-chain nodes.
- 2026-11-04 — (superseded by USDG) **Manual USD↔ETH rate.** An oracle is another trust and failure point; receipts carry the wei amount and the consumer bounds it to ±5% of its own rate. Rejected: Chainlink feed (not verifiably deployed on this chain from here).
- 2026-11-04 — **Resolve Robinhood hosts through DNS-over-HTTPS (`router/net.mjs`).** The dev ISP answers every `*.robinhood.com` lookup with a block-page IP (158.140.186.3), so RPC, docs and explorer all timed out. DoH (Cloudflare, then Google) + system-DNS fallback restores access with no config; local/IP hosts skip it. Rejected: telling users to change DNS/VPN (silent failures for everyone behind such ISPs).
- 2026-11-04 — **Sealed envelopes instead of TLS between peers.** Works over plain-HTTP tunnels and between nodes with self-signed or no certs, authenticates the recipient by the signed box key, and is the same primitive an enclave-bound key would use. Does not hide prompts from the provider. Rejected: mandatory TLS (certificates for home nodes are a blocker).
- 2026-11-04 — **Token audit is an upper bound only (3× chars/4 + 32).** Cheap, no tokenizer dependency, catches gross inflation, cannot catch modest padding. Real fix = probe requests and real tokenizers (roadmap).
- 2026-11-04 — **`ethers` is the one runtime dependency, loaded dynamically.** Writing secp256k1 + keccak + RLP + EIP-712 by hand is a bug farm. Without it the router still works in sim mode. This supersedes the earlier "no dependencies" decision for the chain adapter only.
- 2026-11-04 — **Gossip-learned URLs must be public hosts.** Stops a hostile peer from steering our outbound requests at localhost, LAN or cloud metadata. Operator-typed URLs are exempt so local demos work.
- 2026-11-04 — **Blockscout as the explorer integration.** Robinhood Chain's explorer is Blockscout, so verification and lookups use its public REST API v2 (no API key, same shape on every instance). Explorer calls are best-effort with short timeouts and never gate payments. Rejected: Etherscan-style API (not offered by Blockscout by default).
- 2026-11-04 — **Passphrase env var for encryption at rest, not a keychain.** Portable across Windows/macOS/Linux with no native dependency; opt-in so the zero-config demo keeps working. Rejected: OS keychain bindings (native deps), always-on encryption with a generated key stored next to the data (no real protection).
- 2026-11-05 — **TEE = Google Confidential Space first, buyer pins image digests.** Its token is a standard OIDC JWT (RS256 + public JWKS), carries the container image digest and accepts a custom nonce, so verification is ~100 lines of stdlib crypto and works from any buyer. The nonce binds identity, sealing key and wallet. Trust anchors are the *buyer's* list: a seller (or we) can never vouch. Rejected for now: raw TDX/SEV quotes (need Intel/AMD collateral services and a native verifier), AWS Nitro/Azure MAA (planned as the second platform so we are not single-cloud). Consequences: only local upstreams in TEE mode; ephemeral identity per boot, mitigated by payout sweep + auto-redeem + redeem on SIGTERM; GPU confidentiality unconfirmed.
- 2026-11-05 — **`teeOnly` no longer accepts claims or the demo market's "TEE".** Honesty over convenience: `private` = local upstream or verified attestation.
- 2026-11-04 — (superseded) **TEE attestation not shipped.** It cannot be implemented honestly without TEE hardware and vendor collateral to test against. UI and landing say "claimed".
- 2026-11-06 — **A live listing always beats the simulated market inside one request's candidate set (`plan()` in `router/core/candidates.mjs`).** Found by walking the first-run flow: after connecting Ollama, `model: auto` was still answered by a simulated peer (`[elyra demo engine ...]`, `simulated: true`), because simulated peers were not `explicitOnly` and out-scored the CPU-bound local model. A real app calling `auto` would have received canned text. Now: if any non-simulated candidate matches, only those are ranked; with nothing live the demo market answers as before (a fresh install still has something to show), and a model that exists only in the simulated market stays reachable by name (labelled). Rejected: removing the demo market when a source exists (breaks browsing and `TRY`), or only fixing the UI (the API would still hand out canned text).
- 2026-11-06 — **Opt-in remote admin: one named host, behind a login (`router/http/remote.mjs`); the loopback-only rule is otherwise unchanged.** The owner wants the real panel reachable online. A tunnel or reverse proxy connects from loopback, so the peer-address check proves nothing for proxied traffic; widening the Host allow-list alone would have published the wallet and upstream keys. So: enabled only when `ELYRA_ADMIN_HOST` and `ELYRA_ADMIN_TOKEN` (>= 24 chars) are both set (misconfiguration fails closed); HMAC-signed `HttpOnly; Secure; SameSite=Strict` cookie with a per-boot key; constant-time token check; per-client and global login rate limits; Origin/Sec-Fetch-Site check on writes; proxied requests can never use the localhost path; `/metrics` never reachable through it; `/p2p/*` stays open as before. Rejected: no auth behind an obscure hostname (security by obscurity, and `/v1` would hand free compute to anyone who finds it), Cloudflare Access only (not available to every deployer; can be added in front), CORS from the static site to a remote API (cross-site cookies, larger surface). Residual risk: a stolen token is full control of the node; the global login lock can be used to deny the admin a login for 10 minutes.
- 2026-11-06 — **No static demo; `/app/` on the website goes to the live node.** The recorded demo read as "not real". Replaced by app.elyrainference.com: signed-out visitors get a small try page (real chat, local model only, rate-limited, opt-in `ELYRA_PUBLIC_TRY`); the owner signs in for the panel. The real `/api` is still never exposed to visitors, because it holds the wallet and keys. Rejected: proxying `/api` to Pages; a read-only public panel (too much surface); letting visitors route to paid peers (spends the node's escrow).
- 2026-11-07 — **Wallet sign-in = Sign-In with Ethereum, EOA only, server-built message per nonce; roles admin/user; visitor payments are a separate opt-in flow.** The server builds and remembers the exact EIP-4361 text for each single-use nonce, so domain/URI/chain/expiry cannot be altered and nothing has to be parsed from client text; the cookie reuses the token login's HMAC family with the role inside. A signature proves key control, not identity or funds, so a wallet user gets identity and a larger bounded quota only (per address plus a per-IP cap, since addresses are free), and never `/api`. Admin is an env allow-list (`ELYRA_ADMIN_ADDRESSES`), no database. Paying from a visitor's browser wallet cannot be done by the sign-in session: a wallet cannot sign a voucher per request, and the node does not take custody; that is what the opt-in session-key flow (`ELYRA_PUBLIC_PAY=1`, the page signs each voucher with a throwaway key) is for. Rejected: EIP-1271 verification (needs an RPC call per sign-in and a trusted chain), parsing the client's message and checking fields, JWTs or a user database, a wallet user role on `/v1`.
- 2026-11-07 — **Merging the two repos: one sign-in, one deposit cap, code wins over docs.** elyra-app had a second wallet-account system (`/gw/*`, cookie `elyra_acct`, session tokens in `accounts.json`) next to elyra's SIWE. Kept SIWE (server-built nonce text, signed-out on restart, server-side revoke on logout) and reduced the accounts store to username profiles behind `ELYRA_GATEWAY=1` (`GET|PUT /auth/username`, set once, gates `/pub/chat`); a second cookie and a second signature flow would be two places for the same bug. Likewise the two deposit caps ($20 per wallet from elyra-app, `ELYRA_MAINNET_DEPOSIT_CAP_USD` per node from elyra) became one: `depositCapOf(state.provide)` everywhere, and on a real network the stricter of it and the mainnet ceiling (default 20), so raising it on mainnet needs both. Rejected: keeping both systems behind separate flags (contradictory docs and doubled attack surface).
