## Mainnet fork rehearsal (real USDG code, no funds)

`cd contracts && npm run rehearse:mainnet` forks Robinhood mainnet locally (reads go through a DoH-resolved read-only proxy; writes are refused) and runs the escrow against the real USDG proxy `0x5fc5…d168`: deposit, voucher redeem (exact 12,345,678 units), replay refused, early withdraw refused then allowed after 1 day, no fee-on-transfer, no rebasing; accounting matched `balanceOf(escrow)` at every step. **Finding: a USDG supply controller can burn from the escrow today** (one of four controllers passes the static check); after a simulated burn `deposits[]` exceeded the real balance and over-balance redeems/withdraws revert atomically (`TokenTransferFailed`). The token is also owner-upgradeable. Report: `contracts/rehearsal-mainnet-fork.md`. Nothing was sent to mainnet.

## Security review (2026-11-05, manual, not a professional audit)

An independent read-only review found real problems; all but the documented ones are fixed and covered by regression tests (`router/test/security.test.mjs`, `contracts/test/ElyraEscrow.test.cjs`):

| Finding | Status |
|---|---|
| F1 CRITICAL: a signed receipt with missing/NaN/huge fields made a consumer sign a voucher for the whole deposit | **Fixed**: strict receipt validation, the dollar and token amounts are *derived locally* and must match exactly, prompt/completion bounds, receipts bound to the request nonce, replay set, consumer refuses when escrow < worst-case cost; peer output capped at 8192 tokens |
| F2 HIGH: off-chain voucher check accepted forms the contract rejects (v=0/1, 64-byte) → free service | **Fixed**: exact 65-byte, v∈{27,28} check |
| F3 HIGH: a consumer can drain its deposit by redeeming a self-signed voucher through a second address, so the withdraw delay protects no provider | **Documented limitation** (contract unchanged, README "Trust model"). Mitigation is provider-side: unpaid balance per wallet (served − redeemed on-chain) must stay ≤ `creditUsd` (default $0.50) **including** the next request's worst case; provider auto-redeems (`autoRedeem`, threshold `autoRedeemUsd` $0.25, plus a 60 s sweeper) and refuses with 402 otherwise |
| F4 HIGH: unfunded/duplicate identities got free service; credit keyed by node id | **Fixed**: credit and vouchers keyed by *wallet*; provider verifies the on-chain deposit covers unpaid + worst case *before* creating any state; table capped |
| F5 HIGH: one failing redeem aborted settlement for everyone | **Fixed**: per-wallet redeem, failures reported in `failed[]`, others proceed |
| F6 MEDIUM: impersonation/replay of consumers; wallet "binding" was not proof | **Fixed**: every request carries an ed25519 signature over (provider, ts, nonce, model, body hash), 60 s window, nonce replay cache; wallet control proven with an EIP-191 signature; voucher push is sealed |
| F7 MEDIUM: provider failed open when RPC was down | **Fixed**: fresh reads, 503 fail-closed |
| F8 MEDIUM: abort mid-stream left served work uncounted | **Fixed**: estimated cost accrues as owed |
| F9 MEDIUM: stale `withdrawAt` made the delay one-shot | **Fixed in contract**: 7-day window, single use, own deposit clears it |
| F10 USDG controller burn/blocklist | Documented; transfers are atomic, no on-chain remedy |
| F11 vouchers have no expiry; F14–F17 (cache skew, decimals global, 64-bit ids, no ERC-1271) | Open, low severity |

## NOT verified / simulated (labelled in UI)
- **Testnet token is our own `MockUSDG`** (open mint, labelled MOCK in the UI). The official docs list only the mainnet USDG: `0x5fc5360D0400a0Fd4f2af552ADD042D716F1d168` (6 decimals).
- **Real USDG risks** (Paxos "Global Dollar", upgradeable faceted proxy): transfers can revert for policy reasons and the supply controller can burn from any address, so a deposit can shrink or `redeem`/`withdraw` can revert. The escrow treats the token as a plain ERC-20 that may revert (atomic; state unchanged), but cannot protect against seizure. Mainnet needs `--allow-mainnet`; it ran one $1 smoke trade (see the log below) and is otherwise a capped, unaudited beta.
- **Demo market & catalog numbers**: 29 simulated models / 59 peers / 66 listings (`catalog.mjs`), always labelled `SIM`, never settled, and never shown on the public market page (`/pub/market`). The former "600+ models / 150+ providers" targets were removed from landing copy on 2026-11-08; they are not measured supply. These are historical snapshots, not current live counts.
- **TEE**: the Confidential Space attestation verifier (`router/tee.mjs`) is built and tested against a simulated Google key (47 tests), and buyers accept only container digests pinned in their own trust list; however, **it has not yet run inside a real Google Confidential Space VM** (milestone M1 in `docs/TEE.md`). - **Browser wallet & session-key pay-per-use**: verified end-to-end against a local Hardhat chain with an injected EIP-1193/EIP-6963 mock wallet; **not yet exercised with a real MetaMask/Rabby browser extension** on Robinhood Chain testnet. `ELYRA_PUBLIC_PAY` is off on `app.elyrainference.com` while there is 1 live seller.
- **Contract has had one AI-assisted manual review, not a professional audit.** App-side per-wallet deposits are capped at `$20 USDG` (`maxDepositUsd`) by default. No admin keys, EOA signers only, partial-pay when the deposit is short.

## Known gaps

- Secrets are plaintext unless `ELYRA_PASSPHRASE` is set (scrypt → AES-256-GCM; wrong/missing passphrase refuses to start). **Back up `.elyra/` (identity + wallet); deleting it loses the wallet and any unredeemed vouchers.**
- Sellers behind NAT/CGNAT can sell without port forwarding through a relay (`ELYRA_RELAY_URL` → `<relay>/r/<id>`), and peers share known URLs via gossip, and `ElyraRegistry` provides on-chain discovery (deployed on testnet and mainnet, see `docs/REGISTRY.md`); there is no DHT.
- Reputation is local success/failure, speed, time-to-first-token and probe uptime (sybil-able without paid-history weighting); token audit is an upper bound only.
- Provider risk per consumer wallet is bounded by `creditUsd` (default $0.50 of served-but-unredeemed usage) and `maxDepositUsd` (default $20.00 per-wallet escrow cap); amounts round to 1 USDG unit ($0.000001) per receipt.
- No failover after first byte of a stream. Chat completions only. Redeem is one tx per consumer (provider pays ETH gas).
- Explorer calls (verified badge) are best-effort; the badge hides when Blockscout is unreachable.

## Wallet sign-in (2026-11-07)

`/auth/nonce|verify|session|logout` on the admin host (`router/http/siwe.mjs`): the server issues and remembers the EIP-4361 message per single-use nonce (5 min), verifies an EOA signature with ethers and sets the same signed cookie family as the token login (`elyra_admin` v2, per-boot key, 12 h, logout revokes the cookie server-side), now carrying a role. `ELYRA_ADMIN_ADDRESSES` (case-insensitive) makes an address **admin** (full panel, same as the token; remote admin now turns on with host + token **or** host + addresses); any other address is **user** (identity, `/pub/quota` tier `wallet`, larger hourly limit per address and a 3x cap per IP) and gets 403 on `/api`, `/v1`, `/metrics` and the live feed. This is the only wallet sign-in: after the repo merge the separate `/gw/*` account system of elyra-app is gone, and `ELYRA_GATEWAY=1` only adds the username profile (`GET|PUT /auth/username`, set once) and the `/pub/chat` gate (`401 signin_required`, `403 profile_required`; admin sessions exempt). **Verified:** `router/test/siwe.test.mjs` (nonce replay, cross-host/tampered message, wrong signer, malformed input, cookie forgery and role escalation, CSRF, rate limits and lockouts, expiry and future messages with an injected clock, quota tiers, wallet-only deployments, CSP of the login page), `router/test/accounts.test.mjs` and `router/test/gateway.test.mjs` (profiles through the whole app), and a throwaway node signed in end to end with a local ethers wallet through `panel/try/auth.js`. **Not verified:** a real browser wallet (MetaMask, WalletConnect) against the login page and the public page; smart-contract wallets (EIP-1271) are refused by design; no external review.
